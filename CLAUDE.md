# KrishaParser — памятка для ИИ-помощников

Личный инструмент: ищет на krisha.kz квартиры в Алматы, которые дешевле своих аналогов,
и строит отчёт `report.html`. Владелец читает и правит код сам, поэтому код должен
оставаться простым.

## Как устроено

Один локальный процесс, этапы запускаются через `run.py`:

1. `collect` — `krisha/collector.py` + `parse.py`: страницы списка → таблица `listings`
2. `enrich`  — `krisha/enrich.py`: склейка копий, аналоги, скидка → `metrics`;
               `krisha/benefit.py`: выгода с учётом ремонта и обстановки → `benefit`
3. `photos`  — `krisha/photos.py`: фото с фотосервера → `data/photos/<id>/`, таблица `photos`
4. `vision`  — `krisha/vision.py`: оценка фото ИИ и сверка с текстом → таблица `vision`
5. `analyst` — `krisha/analyst.py`: вердикт ИИ по лучшим кандидатам → таблица `analyst`
6. `report`  — `krisha/report.py` + `report_template.html` → `report.html`

Другой набор настроек: `run.py <команда> --config configs/<имя>.yaml` (своя база и свой отчёт).

Все обращения к ИИ идут только через `krisha/llm.py` (функция `ask`). Провайдер и модель
выбираются в `config.yaml` отдельно для каждого этапа.

## Правила проекта

- **Язык.** Комментарии, сообщения в консоли и тексты отчёта — на русском.
- **Простота.** Без фреймворков, очередей, Docker, ORM. Обычные функции и SQLite.
  Новая зависимость — только если без неё никак.
- **Числа достаёт код, не ИИ.** Цена, площадь, этаж, год берутся разбором страницы.
  ИИ оценивает только то, что кодом не достать (фото, смысл текста).
- **Пропуски не заполняем.** Нет данных — поле остаётся пустым и помечается в отчёте.
- **Ответ ИИ — строго по схеме** (`ANSWER_SCHEMA` в `vision.py`), с проверкой и повтором.
- **Настройки — в `config.yaml`**, не в коде. Фильтры поиска — блок `filters`; из `search_url` берутся только город и границы.
- **Лимит ИИ ограничен.** По умолчанию дешёвая модель (`haiku`); пробные запуски — с малым числом (`vision 3`, `analyst 2`).
- **Каждый этап можно прервать и продолжить**: результат пишется в базу сразу.

## Ограничения сайта (важно)

- Страницы списка отдаются обычным запросом. Паузы 2,5–5 с, один поток.
- Карточки объявлений (`/a/show/<id>`) закрыты проверкой на бота SafeLine.
  **Проверку не обходить**: никакой имитации браузера, решения капч, подмены отпечатков.
  При блокировке сборщик останавливается и сохраняет прогресс.
- Фото качаются напрямую с фотосервера по шаблону адреса. На сервере остаются
  удалённые фото, поэтому берутся самые свежие по номерам.
- Из-за закрытых карточек нет полного описания (в списке ~300 знаков) и координат.

## Проверка изменений

```
.venv\Scripts\python -m unittest discover tests     # разбор страниц, без сети
.venv\Scripts\python run.py enrich                  # пересчёт по уже собранной базе
.venv\Scripts\python run.py report                  # пересборка отчёта
```

Тесты работают на сохранённых страницах в `tests/fixtures/`. Если krisha поменяет вёрстку,
сохраните свежую страницу списка туда и поправьте `parse.py`.

`collect`, `photos` и `vision` ходят в сеть или тратят лимит ИИ — запускайте их осознанно,
для пробы с ограничением: `run.py photos 5`, `run.py vision 3`.

## Что не лежит в репозитории

`data/` (база и фото), `report.html`, `.venv/` — создаются локально.

## Что ещё не сделано

- Координаты (геокодирование адреса), расстояние до метро, собственные зоны.
- Склейка копий пропускает одну квартиру, выставленную с разным числом комнат или годом.
- Тарифы ремонта и обстановки в `benefit` — примерные, не откалиброваны по данным.
- Провайдер `openai_compatible` ни разу не проверялся на живом сервисе.
